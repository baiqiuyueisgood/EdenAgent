# 2026-10-13 工作区搜索两分钟预算与终止修复

用户要求开始修复，并将搜索预算给到两分钟。本轮修复 Eden Agent 的内置 `search_files`；DSH 缺陷报告是排查依据，没有修改参考仓库或客户安装的 DSH。

## 已确认的问题

原 `workspace-search.ts` 的 15 秒检查只在遍历文件之间执行。`readdir`、`open`、`stat`、`read`、`close` 任一步等待不返回，都能绕过该检查；执行中的取消也不能唤醒这些等待。原结果只有 `truncated`，没有说明因匹配数、文件数、目录项数还是时间而停止。

另外，工具执行入口的 `workspace.root()` 会同步调用工作区路径检查。仅将扫描循环挪到子进程，仍会在启动期限计时之前卡住宿主，因此这项检查也必须移入搜索子进程。

## 实现与数据边界

- `workspace-search-process.ts` 使用独立、隐藏的 Node 子进程，只执行只读搜索，不启动 shell 或其他子进程，不重新开启执行沙箱。宿主使用单调时钟计时，默认预算 **120,000 ms**，包含搜索子进程的启动与路径验证。
- 到期或用户取消时，宿主直接终止该搜索子进程，不等待扫描循环恢复。最多另给 **1,000 ms** 等待退出确认；无法确认时返回 `workerStopped=false`，不把退出请求当作已退出。用户取消保留原始取消原因，不伪装成正常搜索完成。
- `WorkspaceService.searchLocation()` 只读取持久工作区选择及预期路径身份。目录存在性、目录类型、真实路径和工作区内路径检查在子进程执行；默认工作区经过 junction／符号链接时保留既有 canonical 身份，被重定向后拒绝执行。
- 扫描在可能挂起的读取之前以及文件关闭之前向宿主传递快照。宿主只保留最近的有界快照；超时返回已经找到的匹配，关闭文件挂起也不会丢掉该文件已发现的匹配。不积攒无界原始搜索输出。
- 保留原先的字面、不区分大小写搜索、文件名匹配优先、默认目录排除、512 KiB 内容上限与二进制／无效 UTF-8 跳过行为。保留最多 2,000 个文件、10,000 个目录项以及工具默认 20／最多 50 个匹配；没有悄悄扩大搜索范围，也没有自动重试。
- 工具修订为 `eden.workspace.search.v2`，模型参数仍只有 `query`、`path`、`limit`。期限及测试用 worker 选择不是模型参数，内部期限覆盖只能缩短，不能超过两分钟。子进程 IPC 输入／输出均进行 schema 校验。
- 中文工具说明明确字面搜索不支持正则、部分结果不能证明不存在其他匹配、遇到期限或数量上限需要缩小范围，以及 `workerStopped=false` 的处理。没有将进程 PID、路径身份或其他内部跟踪标识返回模型。
- `build_server.mjs` 增加搜索子进程制品；`package_server.mjs` 将其与 source map 打包，并在 runtime manifest 记录制品哈希。便携运行不依赖仓库 TS 源码、tsx 或系统安装的 rg。

## 结果契约

保留 `matches`、`scannedFiles`、`truncated`，新增 `visitedEntries`、`skippedFiles`、`stopReason`、`elapsedMs`、`budgetMs`、`workerStopped`。扫描计数包含已经开始读取但尚未完成的文件；`skippedFiles` 统计无法读取或不适合内容搜索的文件，不统计默认排除目录。

| stopReason | 含义 |
| --- | --- |
| `completed` | 在既有排除和内容限制范围内结束遍历 |
| `match_limit` | 达到调用的匹配数量限制 |
| `file_limit` | 达到 2,000 个文件限制 |
| `entry_limit` | 达到 10,000 个目录项限制 |
| `timeout` | 两分钟期限到达，返回最近快照 |

只有 `completed` 对应 `truncated=false`。数量限制按保守原则标记部分结果，即便限制恰好等于最后一项，也不声称已穷尽整个范围。无法启动、异常退出、非法 IPC 或路径验证失败仍明确报错，不改写成“成功但没有匹配”。

## 实际验证

使用仓库随附 Node **22.23.1**，只使用独立临时目录和临时／内存数据库，没有将真实用户数据库当作测试夹具。

```powershell
$edenSearchNode = 'E:\EDEN\Agent\dist\runtime-win32-x64\node\node.exe'
& $edenSearchNode Script/Test/run_typescript_tests.mjs Server/tests/integration/workspace Server/tests/regression/workspace
& $edenSearchNode node_modules/typescript/bin/tsc -p tsconfig.server.json --noEmit
& $edenSearchNode Script/Architecture/check.mjs
& $edenSearchNode Script/Project/build_server.mjs
& $edenSearchNode --test Script/Project/workspace_search_artifact.test.mjs Script/Project/workspace_search_package.test.mjs

# 独立进程中的实际默认两分钟期限，不用 mock 时钟代替等待。
$env:EDEN_SEARCH_FULL_BUDGET_TEST = '1'
& $edenSearchNode --test Script/Project/workspace_search_artifact.test.mjs
Remove-Item Env:EDEN_SEARCH_FULL_BUDGET_TEST
```

工作区专项递归发现 **11 个测试文件、56 项测试全部通过，0 失败、0 跳过**。其中包括搜索匹配与跳过行为、执行前及执行中取消、500／800 ms 挂起期限、部分结果、进程实际退出、异常退出／非法 IPC、文件／目录项／匹配数量限制、字面查询、缩小路径、模型参数边界，以及 managed junction 身份校验；同目录既有工作区与共享目录隔离回归也通过。

两个制品／便携测试均通过：将实际生成的搜索 worker 复制到含中文和空格的临时位置，运行相同宿主搜索监督器；只在临时 worker 副本中使已经打开的真实文件 `FileHandle.read` 永不完成，验证超时保留前一文件的匹配，并用进程存在性检查确认 worker 已退出。最终版本还验证 `FileHandle.close` 永不完成时，同一文件已发现的匹配仍能返回。实际执行打包脚本后，核对 manifest 哈希，并使用包内 Node、包内依赖在不同 cwd 执行搜索成功，不依赖 source／tsx。

默认期限另作真实等待验证：**budget=120000 ms、elapsed=120013 ms、workerStopped=true**，保留已有匹配并确认子进程不存在。短期限使用相同生产监督路径，只在测试内缩短期限；未将该测试开关接入生产运行。

类型检查、Server 构建及差异空白检查通过；架构检查 **1,094 个源文件、0 错误**，已有文件规模提醒保留。首次测试命令误将文件名传给只接收目录的递归发现器，改为目录后通过；首次类型检查发现直接对象字面量的 ForkOptions 声明不包含 windowsHide，改用与现有运行时相同的 typed stdio 启动选项后通过。

## 生效与未覆盖范围

当前源码与 `dist/server` 已构建；在线 Agent 进程和现有发行安装目录没有被替换，需从新源码或新构建重新启动后生效。便携打包验证使用临时目录，并未发布或更新用户安装。

本轮期限仅覆盖内置 `search_files`。`exec_command` 的命令期限、插件、MCP、第三方 grep 与 DSH 的自身策略没有改变。内部快照用于超时返回，不代表已经增加前端实时扫描进度界面；耗时和停止原因在最终工具结果中可查看。Windows 的临时制品与便携运行已验证，未据此宣称 Linux／macOS 或真实断线网络磁盘场景已经验收。

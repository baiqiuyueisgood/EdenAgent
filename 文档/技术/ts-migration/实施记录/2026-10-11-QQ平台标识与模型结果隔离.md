# QQ 平台标识与模型结果隔离

日期：2026-10-11。用户要求修复智能体接收到发布说说返回的真实 `tid`，并记录文档。

## 原因与最终行为

QQ 动作工具此前直接返回 Core 的完整回执，未配置运行时已有的 `modelResult`。`tool-adapter` 在没有投影时使用完整结果，导致 `tid` 与 `request_id` 进入后续模型请求，模型又把说说 ID 当成凭据写入思考和回答。这是工具输出边界缺失，前端隐藏和提示词约束不能替代结果过滤。

现在原始回执先经过 `afterTool` 持久记录，再投影为模型可见结果。QQ 号、群号、机器人选择与表情编号等真实业务选择保留；说说、消息、文件、目录、公告、申请、分页游标及其他资源标识改为短业务引用，宿主追踪字段与文件校验哈希移除。私人 QQ 最近对话中的 Core 消息记录 ID 只隐藏，不误当 OneBot 消息 ID。结果中的成功、失败、未知、确认和排队状态保持原事实。

模型可用 `qqref:qzone:…` 等业务引用执行后续动作。引用是宿主分配的定位值，不是真实 QQ 平台 ID，也不是外部接口凭据；不要求用户抄写平台标识。工具详细参数 schema 同步声明引用，执行时先还原原始参数，再按原流程审批、查询 Core 能力 schema 和验证访问范围。原始平台标识不能直接填入模型操作参数。

## 模块、输入输出与状态归属

| 模块 | 输入与输出 | 所有者与失败行为 |
|---|---|---|
| `modules/tool-results` | QQ 原始结果 → 业务投影；检查点 → 用于恢复的副本 | 无外部副作用；保留业务内容、SDK 关联字段，过滤技术标识 |
| `mon/qq-reference-repository.ts` | 真实标识与目标绑定 → 持久引用；引用 → 真实值 | Mon 数据库；按会话、账号/兼容凭据、Core 地址、机器人及 QQ 群/操作者作用域隔离；缺失或类型错误拒绝 |
| `mon/qq-action-results.ts` | Core 回执 → 隐藏追踪字段并替换标识的模型结果 | 当前宿主工具调用；保存引用采用事务，保存失败标记持久边界错误；已知标识在错误说明中也替换 |
| `mon/napcat-tools.ts` | 模型业务参数 → 宿主实际参数 → QQ 接口 | 调用与回执绑定留在宿主，不把凭据或目标对象序列化给模型；审批仍展示实际操作目标 |
| 联系/文件工具 | 私人 QQ 回执、最近对话 → 状态与业务内容 | 原始回执仍在原投递账本；接收、发送确认、排队不等于已读 |
| `runtime-pi/tool-adapter.ts` | 原始工具结果 → 审计 → 模型投影 | 投影失败立即终止本轮；不回退原始结果，也不再次调用已经执行的工具 |

`qq_action_references` 是新增私有持久表，绑定 `sessions` 外键，并建立作用域索引；追加数据库迁移，既有迁移内容和顺序不改变。引用重启后可用，不能跨会话、账号、机器人或 QQ 群/操作者使用；参考资源类型不能替代说说、消息等不同类别。账号已绑定的会话不因合法令牌续换丢失引用；未绑定账号的兼容会话绑定凭据指纹，凭据变更后需重新查询。

## 历史恢复与边界

会话与角色检查点读取时仅处理提供给运行时的副本：QQ 工具内容投影；从原始回执收集已知技术标识，过滤历史回复、思考、工具参数和压缩摘要中的相关值。会话树 entry ID、父节点关系、SDK 工具调用配对保持不变。持久审计、用户原始数据库及前端历史记录不被批量改写。

历史上没有建立作用域关联的旧回执不会凭当前机器人猜测绑定；旧标识隐藏后，后续资源操作需要通过当前作用域重新查询取得引用。过滤针对 QQ 工具结构字段及已知回执值，不承诺识别用户、第三方网页、其他工具或旧记忆中任意自由文本的所有 ID；也不把所有业务 ID 或所有第三方工具结果统一删掉。

查询、发送与群管理仍由原有权限流程和 Core 二次校验控制；群会话仅当前群，未知写入仍不自动重试。此次没有增加或恢复执行沙箱，没有修改 Core/NapCat 的外部协议，也没有真实发送或删除 QQ 动态。

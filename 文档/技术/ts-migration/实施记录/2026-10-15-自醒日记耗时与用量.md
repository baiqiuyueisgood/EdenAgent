# 自醒日记耗时与用量

用户指定在日记底部已有“状态、本轮定时”旁接入本次自醒的耗时与消耗。前端复用现有 `self_awake.execution`，无需调整协议、模型配置、调度和已有持久记录。

## 实现口径

- `SelfAwakeDiaryFooter` 保持原底部布局，新增耗时和 Token。耗时取运行的持久 `startedAt` 至 `completedAt`，包含执行排队、初始化和工具调用，尚在执行时每秒更新。运行记录每两秒读取，终止后停止轮询并更新列表；顶部刷新同时重读当前执行。
- `self-awake-metrics.ts` 只接收与所选运行 id 一致的执行记录，汇总全部 `model.response`，按 requestId 去重。优先使用供应商 `totalTokens`；缺失时只有输入、输出、缓存读取、缓存写入四项都明确才按分项求和，不重复加 reasoning。
- 全部已请求轮次都有明确用量时显示累计；缺少响应或部分用量时显示“至少”已记录值，无可用记录时显示“未知”。数值来自 SDK 规范化结果，其中缓存写入缺失会被补零，不能把该零理解为供应商实际确认的零；未配置单价不推算费用。
- 用户后续要求清除“缓存写入”展示，明细只列输入（非缓存）、输出和缓存读取。保留 SDK 原始规范化记录和总量口径，不清空模型服务端缓存或任何用户数据。[DeepSeek 官方字段说明](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)只将输入分为命中与未命中，SDK `parseChunkUsage` 对缺失的 `cache_write_tokens` 使用零值。
- `SelfAwakeMetricsPopover` 将耗时和 Token 均作为按钮，点击向上展开同一个统计框。通过 portal 避开日记容器的 overflow 裁切，位置随窗口与滚动更新，限制窗口边界和高度。支持再次点击、外部点击、Esc 和关闭按钮；Esc／关闭按钮将焦点返回入口，切换日记卸载弹框。明细可经键盘及辅助阅读访问。
- 切换日记会清理执行记录并忽略旧请求；组件自身再校验运行 id，避免 effect 执行前短暂展示上一条用量。读取失败显示未知和刷新重试说明。

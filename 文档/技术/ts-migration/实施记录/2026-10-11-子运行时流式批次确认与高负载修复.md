# 子运行时流式批次确认与高负载修复

日期：2026-10-11。用户授权按讨论方案修改源码并验证。没有用真实用户数据库作夹具。

## 故障与复现边界

当前 `StreamCoalescer` 使用事件驱动采样，`writtenAt` 在写完后设置。使用实际 coalescer 和 ProcessPeer、虚拟时钟模拟 1000 次单字符更新：单次写入 250 ms、确认后零调度间隔时生成 2 个持久更新；额外确认/调度间隔 120 ms 时生成 1000 个更新。后者是合并退化的受控复现，不是当前在线会话的性能记录，也不能据此断言写入超过 100 ms 必然失效。

旧设计在合并前仍发送每个 SDK 增量及完整快照，运行时逐条等待 IPC 确认；重载时主进程承担大量序列化、校验、事务及广播工作。客户 Downloads 补丁只直接修改发布包的主进程文件，本次采用源码内的子进程批次方案，主进程和子进程制品须一起构建。

## 实现、状态与失败行为

| 模块 | 行为 |
| --- | --- |
| `packages/runtime-pi/src/process-event-stream.ts` | 每个子运行时独立持有一个在途批次和一个待发快照。首个 delta 即发送，后续约 100 ms 定时合并；消息 ID、角色、delta 类型及内容块边界隔离，深拷贝最后快照并完整累加 delta。每 32 次更新让出事件循环。 |
| 背压 | 待发新增 delta 累计 256 KiB UTF-8 或 1024 次更新时，等待当前及待发批次确认，不删除增量。上限约束新增 delta 和更新数；保留的完整快照随当前消息长度增长，只保留一个待发快照，不把完整历史大小作为逐字符确认触发器。 |
| `process-entry.ts`、`process-runtime.ts` | 原有私有 `event` 调用增加可选交付标记，普通事件仍等待原 IPC。旧主进程可忽略额外参数，新主进程也兼容无标记的旧子进程，不因滚动加载出现未知方法。检查点、模型请求/响应、工具目录刷新和实际工具执行前清空批次；prompt/compact 结束等待持久确认并清除定时器。主进程断开停止未发数据。 |
| 后台失败 | 保存第一次异常，立即请求取消子运行时模型；后续事件、清空和工具执行拒绝继续，不自动重试。主任务与最终清空分别失败时保留两类异常。抑制后台 Promise 未处理拒绝的同时保留失败状态，不能吞错后继续副作用。 |
| Server 回调及 coalescer | 已合并批次直接进入原事务、持久化、广播链，再返回 ACK，不进行二次采样；未标记的直接运行时调用保留兼容采样。事件序号及差量链连续，私有 delivery 标记不进入事件 payload 或对外 RPC。 |
| 多角色与压缩 | 现有角色执行和压缩的回调透传 delivery 标记；账号作用域、角色消息投影、权限和工具操作身份不变。 |

运行结束、取消和存储失败验证了没有迟到写库。强制杀进程仍可能丢失尚未确认的在途/待发增量；慢 ACK 时缓冲等待可以超过 100 ms，不能宣称崩溃最多丢 100 ms。关键边界以持久 ACK 为准，事件仍先落库再广播。

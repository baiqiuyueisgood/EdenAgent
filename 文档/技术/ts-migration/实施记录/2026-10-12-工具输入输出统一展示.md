# 2026-10-12 工具输入输出统一展示

用户要求所有工具的输入和输出统一识别换行。本轮接续 [工具结果换行显示修复](2026-10-12-工具结果换行显示修复.md)，将通用结构化展示覆盖主聊天、对话面板、桌宠气泡、角色页历史和自醒工具详情，不再根据工具名称决定普通 JSON 结果是否可以分行查看。

## 展示规则与覆盖

- `tool-data-display.ts` 统一解析外层 JSON 和常用字段标签；`ToolDataView.tsx` 递归展示对象、数组和文本叶节点，`ToolParameters`、`ToolOutput` 分别作为输入／输出入口。
- 字符串中的实际 LF、CRLF 和缩进使用文本节点与 `white-space: pre-wrap` 展示。根字符串、数组、嵌套对象，以及 `false`、`0`、`null`、空字符串、空对象和空数组均保留；已解析 JSON 可以折叠查看完整原文。
- 不递归解析字符串本身含有的另一段 JSON，不替换字面 `\n` 或分号，不把脚本、Windows 路径或工具内容当作 HTML 执行。普通文本和不完整／非法 JSON 按原文显示。
- 深层对象默认折叠，集合超过 12 项默认折叠；展开后每次最多增加 50 个子项，通过“显示更多”访问剩余内容。单个长字符串保留全文并在文本块中滚动，不静默截断。
- `ToolCard` 的一般结果和错误详情、`ChatDialogPanel`、`DesktopPetChatBubble`、`CharacterPage` 和 `SelfAwakeToolCard` 接入共享组件。自醒先按已有逻辑拆开工具内容包装，再将解码后的值传入展示，避免第二次解释字符串中的转义；原始包装保留为“原始回执”。
- 命令工具继续使用 stdout／stderr 专用分栏、退出码、空结果和截断提示；其 JSON 识别使用相同外层解析入口。标准输出内容本身保持文本，不额外解释成 JSON。工作区补丁保留已有差异展示。

这次修改只影响前端展示。展示的数据仍来自既有工具事件和结果，不新增读取宿主私有回执，不改变模型结果、权限、业务 ID、执行审计或会话数据。卡片摘要仍为单行预览，展开正文保留多行。

## 实际验证

使用仓库随附 `dist/runtime-win32-x64/node/node.exe`（22.23.1），在 `frontend/web` 执行：

```powershell
$edenNode = 'E:\EDEN\Agent\dist\runtime-win32-x64\node\node.exe'
$edenToolTests = @(
  'tests/tool-data-display.test.mjs',
  'tests/tool-input-display.test.mjs',
  'tests/tool-command-display.test.mjs',
  'tests/tool-lifecycle.test.mjs',
  'tests/tool-connection-recovery.test.mjs',
  'tests/self-awake-tool-summary.test.mjs',
  'tests/self-awake-model-rounds.test.mjs',
  'tests/self-awake-context.test.mjs',
  'tests/pet-dialog-segments.test.mjs'
)
& $edenNode --experimental-strip-types --test @edenToolTests
& $edenNode scripts/check-theme.mjs
& $edenNode ../../node_modules/typescript/bin/tsc --noEmit -p tsconfig.json
& $edenNode ../../node_modules/vite/bin/vite.js build
& $edenNode --experimental-strip-types --test tests/tool-data-interaction.test.mjs tests/tool-command-interaction.test.mjs
```

结果：**47 项回归与 2 项隐藏 Electron 实际交互通过，合计 49 项，0 失败、0 跳过**。主题检查覆盖 296 个文件，Web 类型检查和生产构建通过。Vite 仍有既有大 chunk 提示；独立 Electron 夹具的 IIFE 打包有 `import.meta` 警告，不影响本轮交互验证。

新增通用展示回归覆盖多层对象／数组、三个样式入口、实际对话面板、自醒结果包装、原始 JSON、字面转义、HTML 惰性文本和 1000 层嵌套数据的惰性展示。Electron 夹具使用实际 `ToolCard` 分别展示搜索、文件和 MCP 命名的合成工具结果，并验证 125 行集合的 50／100／125 分批加载、最后一行的换行、500 行文本滚动以及对话面板内操作不触发推进。命令卡片夹具确认已有 stdout／stderr 展示兼容。

首次验证发现旧测试直接用 Node 加载新增了无扩展名依赖的前端 TS 模块而失败，已改为使用 Vite SSR 加载以符合前端模块解析。当前 TS 配置下布尔联合类型缩窄需明确比较，已修正共享组件和预览入口。修正后相关回归重新运行通过。

截图 `dist/verification/tool-data-results.png` 和 `dist/verification/tool-command-results.png` 已实际读取核对：输入、嵌套结果和 stdout／stderr 保持分行；原始 JSON 默认折叠。通用夹具截图增加展开高度及浏览器绘制帧等待，避免捕获到仅有标题的动画起点，随后重新运行并核对完整截图。

全部测试使用合成输入／输出、系统临时目录和独立 Electron 用户目录，不使用用户数据库，不执行命令示例中的 HTTP 请求或实际业务工具。角色页完整操作、真实桌宠窗口及真实插件／MCP 联调没有在本轮逐项执行，接入由类型检查及共享组件／已有规范化回归覆盖。

开发版刷新前端即可使用；便携客户端需要更新 Web 制品。本轮未替换运行中的服务或发行包。

# 2026-10-13 流式长输出持久化与心跳修复

用户在[客户机报告复核](2026-10-13-客户机长任务截断报告复核.md)后授权开始修复。本轮修改当前源码中已确认的全文处理和持久化回退问题，并加固进程期限判断；没有取得客户机数据库、现场日志或其制品，因此不能认定报告里的全部中断都已定位到同一根因。

## 实现

### 捕获流式快照和让出事件循环

- `packages/api/src/json-snapshot.ts` 提供 JSON 快照：复制可变容器，复用不可变字符串，保留共享对象关系。处理 toJSON、缺省字段、数组空位、非有限数字、原型名称字段和循环／BigInt 拒绝，不通过 stringify／parse 复制累积正文。
- `packages/runtime-pi/src/harness-runtime.ts` 的 SDK 事件捕获改用该快照；请求、响应、检查点等其他持久边界仍保持原来的校验和提交流程。
- 子进程 `ProcessEventStream`、宿主 `StreamCoalescer` 的缓冲及增量基线也采用结构快照。累积处理约 5 ms 后主动让出事件循环；宿主已经合并的批次立即落库分支同样执行让出。
- 保持约 100 ms 采样、一个在途批次和一个待发快照、256 KiB 新增 delta／1024 次更新的背压限制。语义事件、检查点与工具边界继续等待全部已接受批次提交，没有通过丢弃内容减少负载。
- 5 ms 是让出检查阈值，不能抢占单次同步 SQLite 提交或一次较重的对象遍历，不代表事件循环延迟的硬上限。

### 分别保存消息正文和 SDK partial

- `Server/src/modules/sessions/message-storage.ts` 与 `stream-persistence.ts` 新增磁盘格式 `eden.message.delta.v2`。消息正文保存快照或相对前一个已提交消息的补丁；SDK `partial` 可以相对当前正文或前一个已提交 partial 保存补丁，也可以独立快照。
- partial 与正文的字段、内容、键顺序不同不再导致整个事件退回全文存储。缺省 partial、null／标量 partial、字段删除、思考和工具参数等保持原值。选择补丁使用结构长度估算，不为比较大小反复序列化累积全文；最终实际落盘仍使用一次 JSON 编码。
- 保持按会话、轮次、消息隔离的基线和 128 层快照界限；重建 writer 时从新快照开始。只有事务提交后才更新基线。缺失／损坏的基线仍明确报错，不返回不完整文本。
- 公共事件先持久提交，再广播原始完整载荷；磁盘私有编码不进入 WebSocket、模型或前端。读取同时支持原始历史、v1 快照／增量和 v2。
- 追加数据库迁移 135，将 `realm_meta.event_payload_format` 标为 v2，并提高 user_version；不改写或清理旧事件。旧宿主已有的 schema 版本检查会拒绝打开新版本数据库，避免旧 reader 把新编码误当公共载荷。

### 心跳和取消期限

- `packages/runtime-pi/src/process-deadline.ts` 用单调时钟判断期限，系统时间校正不会直接改变失联时长。
- 心跳和合法业务 IPC 都作为子进程仍在响应的证据。默认启动 60 秒、心跳 15 秒、取消确认 2 秒的期限保持不变。
- 初次超期后只安排一次确认窗口：正常调度 200 ms，检测到宿主定时器明显迟到时最多 1000 ms；窗口结束后通过 setImmediate 给排队 IPC 一次处理机会，再确认超期。未恢复通信的进程不会因宿主持续迟到而无限获得新期限。
- 取消采用相同的有界确认方式，不让其他普通心跳延长取消期限；确认回复成功即清理全部计时器。真正卡死／崩溃的子进程仍关闭 IPC、拒绝活动请求并被终止。
- 这是进程存活检查，不是模型供应商网络请求的超时。期限执行仍依赖宿主获得调度，不能保证宿主永久冻结时按墙钟准确终止。

- 真实子进程产生 **3,145,728 字节**的思考及工具参数内容，给 SDK partial 单独追加字段；持久化 **32 个更新批次**，原始累积载荷 **182,488,618 → 9,447,104 字节**，约减少 94.8%。正文、delta 合并与数据库新连接回放逐项一致，工具只执行 **1 次**，模型主调用 **2 次**。源码独立样本约 7.1 秒、编译制品并行验证约 19.8 秒；这些是本机合成压力数据，不代表客户硬件延迟或供应商性能。

## 生效与边界

源码和本地 Server 编译产物已更新，在线进程、客户机安装和便携发行包未替换。使用配套新宿主与子运行时制品并完整重启后生效；新版本数据库不能直接交给旧宿主打开。

没有自动删除旧 events、归档用户历史、执行 VACUUM 或将 FULL 改为 NORMAL。客户机已经膨胀的文件不会因新写入格式自动缩小；本轮降低后续重复增长，保留恢复与审计。没有新增浏览器界面或修改模型的安全／角色提示。

本轮解决的是已复现的全文回退和重复捕获开销，并通过独立压力验证了调度与进程监督。客户机原有 8 次心跳中断、3 次 aborted 和 1 次取消超时是否分别消失，需要更新客户机后使用其现场证据验收。

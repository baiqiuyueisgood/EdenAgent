# Electron 中文日志编码修复

日期：2026-10-13。模块：桌面源码启动器与开发日志转发。

## 原因与输入输出

用户日志中的 `璇锋眰 MonCore 鎺ュ彛澶辫触` 原文为“请求 MonCore 接口失败”。
`main.cjs` 源码和 IPC 内的字符串均正确；问题发生在 Electron 的终端输出。
Windows 控制台代码页为 936 时，Electron 直接继承终端写入的 UTF-8 字节被按 GBK 解读。
在独立 PTY 中精确复现相同乱码；写入独立临时目录的 JSON 显示主进程原文和 preload 收到的 IPC 错误均完整。
因此没有对 IPC 消息做猜测性转码，也没有修改全局代码页或用户终端设置。

新增 `frontend/desktop/Script/launch-electron.cjs`，保持 Electron 参数、stdin、退出码和终止信号转发，
stdout/stderr 改由 Node 父进程分别以流式 UTF-8 解码后输出；Windows TTY 使用 Node 的 Unicode 控制台路径。
多字节字符跨数据块时由流解码器保留，父输出流不随子输出结束而关闭，退出结果在 `close` 后传播。
启动器清除继承的 `ELECTRON_RUN_AS_NODE`，避免将桌面错误启动为普通 Node。

根 `npm run dev` 及桌面 `dev/start` 接入该启动器；独立 `dev:desktop` 的二次转发也明确按 UTF-8 解码。
输入仍为原有 Electron 命令、环境和日志，输出仍为原 stdout/stderr 与退出结果；不改变 Core 请求、鉴权或业务错误。
MonCore 不可达时继续显示真实失败，只修复日志呈现。

## 验证

- 隔离 Windows PTY，控制台代码页 936：修复前 `请求` 显示为 `璇锋眰`，修复后中文与 emoji 正常；完成后恢复该隔离控制台原代码页。
- 实际 Electron 42.4.0 隐藏窗口、项目 preload 与 IPC router，临时 userData/sessionData：中文错误、成功值及输出管道完整。
- 按单个字节写入中文及 emoji，检查多字节边界；检查末尾无换行输出及 Electron 非零退出码 7 原样传播。
- Node 24.21.0 执行 8 个相关测试文件，36 项全部通过，无失败或跳过：
  `console-encoding`、`command-router`、`core-command-handlers`、`renderer-console-message`、
  `process-lifecycle`、`desktop-runtime-contract`、`agent-server` 与 `frontend/tests/process-runner`。
- 三个修改的生产脚本通过 `node --check`；主仓库及 frontend 的 `git diff --check` 通过。
- 首次退出夹具未结束 Electron 事件循环导致测试超时，改为显式 `app.exit(7)`；随后断言发现 Windows Electron 自带前置空行，保留并只忽略此前置空行，最终复验通过。

复现探针与前后结果在忽略目录 `.artifacts/desktop-ipc-encoding-20261013`；各窗口均隐藏，使用独立临时数据目录。
未访问真实用户数据库、登录凭据或模型，未重启当前运行服务、更新安装包、提交推送或推进版本。
源码启动脚本无需重新构建 Web；当前开发进程完整退出后重新 `npm run dev` 加载。

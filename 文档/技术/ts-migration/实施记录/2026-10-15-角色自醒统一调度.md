# 2026-10-15 角色自醒统一调度

## 归属和行为

- 自主自醒：按世界、Core 账号与角色归属一个时钟。专用后台会话承载执行上下文，后台会话不各自拥有长期时钟。普通聊天设置自醒时复用或创建该角色的专用后台上下文，核对账号连接后绑定模型。
- 明确的定时事项：继续使用备忘提醒，保留独立截止时间。旧普通会话的 v2 定时执行按一次任务处理，完成后关闭，不凭空增加十二小时循环；新自醒工具统一按角色安排。
- 兜底：属于角色时钟，空计划十二小时兜底、显式计划最迟实际启动后二十四小时；全局入口只负责引导，角色范围接管后不再额外排队。开机入口重查角色时，Agent 复用现有计划或近期已完成执行，不提前有效的未来计划。

Server 的角色注册表和成员关系位于 self-awake；jobs 在排队、替换、恢复、延期和领取时校验归属，数据库也阻止一个角色同时保留两个待执行计划。历史未知执行和等待外部动作继续占用角色执行位，不在合并时重试未知副作用。账号、角色和世界保持隔离。

MonOs 继续兼容 v2 请求，在能力租约中新增 roleScopes，计划增加 scope_kind（role/session_task/retired）和 watchdog 动作。退役请求和延迟回执不能重新开启旧范围。根调度器读取账号绑定的 role-coordinator.json 并交接，暂停的角色不能被全局兜底重新开启；不让 Agent 伪造 MonOs 的状态或执行时间。

## 遗留计划

启动时合并同角色后台的 queued 计划，选择最早时间作为唯一下一次自醒。原任务保留，标记为已合并；原始正文、时间、来源会话另存 self_awake_merged_plans，不删除日记、会话、运行或审批。各旧范围通过持久 outbox 发出取消，包括没有待执行任务但仍有兜底的范围。

合并事项以历史打算进入下一轮，明确禁止把它们当作新的用户指令或逐条执行义务。实际完成这一轮后标记已核对，避免每次反复注入；完整原始记录仍保留。执行事实只取自 agent.agent_start 的持久激活。

维护入口 Script/Project/consolidate_self_awake.mjs 默认只读；应用要求账号绑定、精确指纹和空闲状态，取得写锁后再核对，不调用模型。所有自动测试使用独立临时数据，实际账号只进行授权维护。

# 2026-10-12 前端工具参数换行与可读性修复

智能体聊天页展开 `exec_command` 时，原实现直接展示序列化 JSON。`command` 中的真实换行在 JSON 字符串内显示成 `\n`，引号显示成转义文本；长脚本只能依赖软换行，正文字号又随窗口高度缩小，造成截图中的密集排版。本次修改参数展示，不改变执行参数或历史记录。

## 展示行为

- `tool-input-display.ts` 仅解析一层合法 JSON。顶层字符串参数按解码后的原文显示，命令保留真实换行、缩进和引号；Windows 路径、正则和脚本中的字面转义保持原值，不直接替换 `\n`。
- `ToolParameters.tsx` 分块展示各字段，常见字段显示“命令”“工作目录”“路径”等标签。数字、布尔值、空字符串和 `null` 不遗漏，嵌套对象与数组保持格式化 JSON。未知字段保留名称。
- 参数、命令详情及普通输出正文的最小字号为 13px，行高为 1.65，仍跟随现有聊天字号设置；长文本允许软换行，超过 48vh 后在文本块内滚动，完整内容不截断。差异补丁仍使用原有逐行展示。
- 卡片标题显示解码后的简短摘要，命令优先于其他字段；卡片保持默认折叠。展开后可单独打开“原始参数（JSON）”查看完整原文。
- 无效、非 JSON 或尚未完整的流式参数按原文显示；参数仍作为 React 文本呈现，HTML 不执行。

状态、审批、子任务入口、原始操作记录和宿主给模型的结果投影保持原有职责。前端已有的 `memo` 优化保留。

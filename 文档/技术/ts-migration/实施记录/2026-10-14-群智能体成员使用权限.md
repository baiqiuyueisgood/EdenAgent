# 群智能体成员使用权限

日期：2026-10-14。用户授权将超级管理员的群模式开关权限与群成员的智能体使用权限分开。

## 行为与权限归属

- 个人超级管理员仍管理本 Bot、本群的 `/模式` 开关；普通成员和仅拥有群管理员身份的成员不能修改开关。
- 群已在 Core 获准访问并开启 `group_agent` 后，未被拉黑的成员可通过既有 @、名字或关键词触发，无需逐人登记私聊白名单或超级管理员。真实发言人仍来自受信 BotCore 消息元数据。
- 新增 Core `group_agent_access.resolve_group_agent_access`，一次读取 Bot 的准入规则，显式拒绝被拉黑的群或成员、无群授权及停用策略。群准入不能变成私人准入。
- `allow_actions` 取群策略与发言人个人超级管理员权限的交集。普通成员及个人 `admin` 成员仅查询当前群；群规则即使为 `true`，也不会将管理员的修改权限借给普通成员。
- Core 的 Agent 群工具 HTTP 入口按实际群与发言人重查，能力目录同步过滤群写操作；伪造或过期的 Agent 写标记不能绕过 Core。既有跨群、账号、私聊、事件及本地工具限制继续生效。
- 显式配置的群戳一戳智能体使用相同准入；私聊戳一戳仍需个人超级管理员。
- 最终文本生成和图片渲染后、下发群回复前重查授权；途中拉黑、关闭模式或撤销群授权时不发布最终正文及图片。失败沿用现有错误协议。

## 调用链与状态

BotCore 沿用后端 `chat` 准入和既有触发元数据，无需新增本地权限状态。Core 将机器人、群、实际发言人和收紧后的 `allow_actions` 传入现有 `qq-group-turn.v1`；Agent 沿用按机器人、群、发言人分开的持久会话。私聊审批、附件暂存和角色记忆不共享给群会话。

没有数据库 schema、协议或正式产品版本变化。更新的权限事实由 Core 持有，群开关继续持久化在现有自动化规则中。源码工作区原有的 100 MB 文件收发、对话和记忆等改动保留。

# 2026-10-12 TUI 交互恢复与状态展示优化

用户在阅读 dsh、OpenCode 和 pi 的 TUI 源码分析后要求开始优化。本批完成优先处理的四项：失败输入恢复、断线会话恢复、工具结果展示、统一状态区。实现仍位于独立 `Server/tui` 客户端，通过公开 RPC 访问宿主。

## 已完成行为

### 输入恢复

- 普通消息及 `/steer`、`/followup` 提交时保存内存快照。明确失败且编辑器没有被继续修改时自动恢复；继续编辑过、已切换会话或结果未确认时，保留在原会话的待恢复记录中。
- `/restore` 恢复待确认输入，仅恢复编辑器，不发送消息。当前已有其他草稿时拒绝覆盖。普通失败命令不会覆盖待恢复消息。
- 首页和每个会话拥有分别保存的草稿与内存输入历史。切换账号清除这些内容；迟到的旧账号失败不能写入新账号编辑器。
- 密码、用户名和提问答案不保存为消息恢复快照。没有新增磁盘历史或跨重启草稿恢复。

### 断线与取消

- 断线后按 0.5、1、2、4、8、15 秒的等待间隔尝试连接，最多 6 次；这些是每次尝试前的等待，连接和身份验证本身的耗时另计。健康连接不周期重建。
- `/reconnect-stop` 停止自动重连并取消当前连接尝试；`/retry` 手动重试。退出、退出账号和重新登录停止自动流程；取消后的迟到认证结果不能恢复已取消的连接状态。
- 重连读取当前能力令牌文件；Mon 身份仍通过 Core 验证，认证过期回到登录。不会为了重连启动 Server，也不会重发消息或副作用 RPC。
- 原会话重新读取消息、计时、操作、事件、审批、提问与模型状态。历史加载结束前到达的事件会先缓冲，在所有读取完成后应用并按序号去重。

### 工具结果

- 执行中、完成、失败和结果未确认分别展示。摘要包含文本结果或错误；失败摘要优先显示 `stderr` / 错误信息，工具耗时来自公开事件或操作记录。
- Ctrl+D 或 `/details` 展开参数与结果详情。较长参数和结果有明确截断提示，大型 `data` 内容显示长度说明；正常业务 ID 不做全局删除。
- `operation.list` 的近期公开快照补回消息历史游标之前的工具结果，和消息按时间合并。最多读取最近 500 条操作；这不是完整的全部历史工具分页。
- 展示改动不改变宿主给模型的结果投影；模型隐私 ID 边界仍由宿主负责。

### 状态区与本轮计时

- 会话页状态区同时显示世界、会话角色、模型、服务端会话工作区、运行阶段、待审批 / 提问和上下文用量，窄窗口裁切显示。
- 会话工作区来自 `workspace.info`；`/refresh` 可以重新读取。首页显示明确标记的启动目录，不把它当作会话工作区。
- 耗时定义为当前这一轮回答，从 `turn.started` 到完成、失败或中断，包含工具与等待审批时间。切换会话或重连从 `session.timing.read` 恢复；完成后停止增加，新轮次重新开始。
- 连接正常且回合运行时用本地单调时钟每秒刷新；断线时冻结，恢复连接后同步权威快照。没有每秒请求计时 RPC。

## 实现文件

`app.ts` 组装流程；`input-drafts.ts` 管理输入快照和会话草稿；`reconnect-loop.ts` 管理有界退避；`auth-flow.ts` 与 `rpc-client.ts` 处理取消和未确认请求；`reply-clock.ts`、`status-view.ts` 提供计时与状态展示；`tool-view.ts` 展示实时与历史工具结果。命令处理移到 `session-commands.ts`，保持客户端边界并控制单文件和函数复杂度。

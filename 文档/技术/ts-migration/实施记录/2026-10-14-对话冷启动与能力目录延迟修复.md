# 对话冷启动与能力目录延迟修复

日期：2026-10-14。承接用户要求查找根本问题并修复，前一轮只读时间表见 [首字延迟排查](2026-10-14-对话首字延迟排查.md)。

## 根本原因与修改

前一轮实际聊天在模型请求之前等待 8.5～14.1 秒；本轮进一步确认两处可复现的本地开销。

1. 每轮隔离进程重新解析大量分散的依赖文件。原构建只打包项目源码，pi、Zod 和 TypeBox 仍外置；
   源码开发入口又逐轮经过 tsx 和模块解析。因此，仅将 worker 编译成 ESM 仍有 3.3～7.6 秒初始化。
   在独立相同回环模型探针中，打包 pi 后约 1.4 秒，将 Zod／TypeBox 一并打包后降至 346／410 毫秒。
   根因是重复依赖加载，进程创建本身不能解释原先的全部耗时。
2. `SessionCapabilities.visible` 对每个工具重复调用 `this.scope`，而 bootstrap 的 scopeProvider
   会读会话、创建工作区服务并解析规范目录。Windows 的 realpathSync 涉及多次 lstat，目录数量将这项工作放大。
   CPU 采样的主要热点链路为 `visible → scope → forSession → WorkspaceService/WorkspaceLocation → realpathSync → lstat`。
   初始三次工具目录装配 505／469／501 毫秒，调用解析 458／448／485 毫秒；基线数据及热点摘要来自本轮工具输出。
   这与实际日志中调用前／刷新前反复约 1.2～1.5 秒等待相符，但不将两种不同数据规模的时间直接相等。

`Script/Project/build_server.mjs` 将 runtime-process 单独构建，公开 SDK、Zod、TypeBox 一并打包；
主入口保留原外置依赖。SDK 版本和公开导入接口保持不变，没有修改 node_modules 或引入 pi 私有接口。
`dev.mjs` 与默认 `start_server.mjs` 先构建当前源码再启动制品；`--built` 明确使用已有制品。
Web 保留 Vite 热更新，Server 代码变更需重启开发入口。

能力目录在每次同步遍历中复用已读取的作用域，当前选择批量校验共享此次作用域，加载技能的可见列表只计算一次。
没有跨调用缓存工具 registry、账号或工作区；调用解析及审批后的 assertCurrent 仍重新读取并验证权限／版本／工作区。
仍为每轮新建并销毁隔离进程，不复用角色状态、凭据或旧审批；存储提交顺序、看门狗、取消及进程边界保持。

## 测量与真实验证

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| 独立 worker 初始化 | 源码约 5.5～5.7 秒；旧编译入口 3.3～7.6 秒 | 完整打包约 0.35～0.41 秒 |
| 合成宿主工具目录装配 | 约 0.47～0.51 秒 | 首次优化后约 0.06～0.09 秒 |
| 合成宿主调用解析 | 约 0.45～0.49 秒 | 约 0.04～0.05 秒 |
| 完整临时服务至首次模型请求 | 本轮未运行完整旧制品对照 | Node 22 两轮 724／643 毫秒 |
| 完整临时服务至首个正文事件到达客户端 | 本轮未运行完整旧制品对照 | Node 22 两轮 814／720 毫秒 |
| 真实 DeepSeek 合成问候 | 不与原用户历史会话直接做性能倍数对比 | 300 毫秒发请求，1675 毫秒首正文 |

完整链路使用实际编译的宿主／worker、磁盘 SQLite、已生成能力目录及真实前端 EdenAgentRpcClient，
通过回环 WebSocket 和立即回复的 HTTP/SSE 模型完成两个独立回合；第二轮模型请求保留第一轮回答，
两轮分别持久保存检查点，并确认正文事件与回合结束顺序。后续标准制品入口复跑得到相近结果。
这是独立本地夹具，不是在线主窗口点击到绘制的完整性能轨迹，不能据此保证所有真实模型回答均在一秒内出现。

真实 DeepSeek `deepseek-v4-flash` 使用已有供应商配置，只读取得连接，保持原 `reasoning=high`，
仅运行一次合成问候，无工具、真实历史或用户日记；模型请求数为 1。配置密钥没有打印或写入结果。
模型思考、复杂任务、多轮工具和网络延迟仍影响正文时间，未擅自降低用户思考设置。

探针与去敏结果位于忽略目录 `.artifacts/latency-audit-20261014/`：
`runtime-startup-result.json` 为初始样本，`runtime-bundled-result.json` 为完整打包探针，
`host-first-after-*`／`host-after-*` 为优化后的采样；初始热点摘要已在工具输出中提取，未把优化后曲线当作初始曲线。
`compiled-turn-result.json` 为 Node 22 完整临时服务结果，`live-provider-result.json` 为真实供应商结果。
